= Concepts
:description: Indexer, Processor, ClassLoader SPI, static bytecode generation.

== Indexer

`vauban-indexer` walks the classpath / module-path at compile time and produces a **bean index**: CDI-annotated classes, their scopes, qualifiers, interceptors, decorators. The static equivalent of Weld's runtime `BeanArchive`.

== Processor (APT)

`vauban-processor` is a `javax.annotation.processing.Processor` that consumes the index and **emits one `_Factory` per bean** via the Class-File API. The generated bytecode:

* exposes a no-arg constructor;
* implements `BeanFactory<T>`;
* knows how to instantiate the target with its dependencies already resolved.

[NOTE]
====
The runtime never reflects on beans. Everything it instantiates flows through the generated `_Factory` classes.
====

== ClassLoader SPI

`vauban-classloader-spi` exposes `PluginContext`, `ByteSourcePlugin`, `ArchiveReader` — used by `vauban-sjar` to load `_Factory` from signed archives (`.sjar`). Lets you embed extensions without `add-opens`.

== Scopes

CDI 4.1 Lite implemented:

* `@Singleton`, `@ApplicationScoped` — single instances for the container lifetime.
* `@Dependent` — multiple instances, lifetime tied to the injector.
* `@RequestScoped` — available when a contextual transport is wired in (Cassini or Foy).

== AOT compatibility

No `Class.forName`, no `Method.invoke`, no `Class.getDeclaredFields()` at runtime. Everything goes through `MethodHandles` or directly through generated bytecode. Compatible with:

* GraalVM `native-image`, no `reflect-config.json` needed.
* Project Leyden CDS.
* Minimal JLink images.

== Tooling

* `vauban-maven-plugin` — orchestrates the `index → process → generate → analyze` pipeline.
* `vauban-junit` — `@VaubanTest` JUnit 5 extension that boots a minimal container for tests.
* `vauban-test-suite` — official integration test suite.
