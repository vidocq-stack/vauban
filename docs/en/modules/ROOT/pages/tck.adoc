== Tests intentionally skipped

[cols="3,5"]
|===
| Category | Reason

| Runtime portable extensions (`Extension`, `BeforeBeanDiscovery`, `AfterBeanDiscovery`)
| Out of the Lite profile. Vauban implements only Build Compatible Extensions.

| `@ConversationScoped`
| Out of the Lite profile.

| `PassivationCapable` / passivation
| Out of the Lite profile: passivation is a CDI Full feature, and Vauban is not certified for it. Vauban does not validate passivating scopes at deployment. Every managed bean is `PassivationCapable`, though, producer and synthetic beans included (the built-in beans are not), and the `@SessionScoped` instances, their client proxies and the built-in `Event`, `Instance` and `BeanManager` they hold move to another container when written, for Foy's session move across a Vidocq dev swap (xref:internals.adoc#session-swap[Session entries across a container swap]). CDI Lite stays at 774/774.

| EL wired into managed beans
| Out of the Lite profile. `jakarta.el` is required only as a spec dependency, not activated on application beans.

| `@Specializes`
| Out of the Lite profile (deferred to a possible Full profile).
|===

== Language model TCK [.tag-new]#NEW#

The core TCK never calls the language model TCK (`cdi-tck-lang-model`), which checks the `jakarta.enterprise.lang.model` API that build compatible extensions read. `LangModelTckTest`, in `vauban-tck-runner` under `-Ptck`, runs its `LangModelVerifier` from a build compatible extension, with the type annotation checks on, in the three places Vauban builds that model:

* at start, when the extensions run as the container starts;
* in the annotation processor, at compile;
* in a deployment frozen at build, whose start then loads the record and runs no extension.

Each place reports 21 tests: `verify` as the TCK runs it, then each of its 20 steps on its own, so that a failing step does not hide the next.
A step that fails for a known bug is reported as skipped, naming that bug; `KnownLangModelGaps` lists them, one line each, and a listed step that passes fails the run until its line is removed.

[cols="2,1,3"]
|===
| Steps skipped | Where | Bug

| `verify`, `PlainClassMembers`, `InheritedMethods`, `InheritedFields`, `InheritedAnnotations`, `BridgeMethods`, `RepeatableAnnotations`
| Everywhere
| `BUG-20261117-42`, no inherited members; `BridgeMethods` and `verify` also `BUG-20261117-43`, synthetic members listed

| `EnumMembers`
| In the processor
| `BUG-20261117-42`
|===

== Reproduce locally

[source,bash]
----
cd vauban
sdk env
mvn install -DskipTests -q && mvn test -pl vauban-tck-runner -Ptck
----

The runner uses Arquillian + TestNG. The Surefire report lands in `vauban-tck-runner/target/surefire-reports/`.

[NOTE]
====
Per the workspace constraint, `vauban-tck-runner` is included in the Vauban reactor — unlike `cassini-tck` or `foy-tck`, which are detached because of ShrinkWrap Maven Resolver. The CDI TCK does not depend on ShrinkWrap Resolver in this configuration.
====
