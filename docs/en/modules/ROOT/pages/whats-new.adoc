= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:internals.adoc#generated-code[No reflection per request for request-scoped and dependent beans] — the interceptor bindings, the annotations of the methods, the constructors, the `$$init` handle of the intercepted subclass, the producer method and the generic type of an injected field are read once per class (or once per factory), not at each request: a request-scoped resource with dependents and interceptors costs no reflective call in Vauban once it has been served (VAU-PERF-009).
* xref:internals.adoc#generated-code[Generated code and reflective fallback] — one table lists what Vauban generates, which tool generates it and when, what uses it at run time and what runs when it is missing, followed by when the fallback runs and how to tell which path ran.
* xref:internals.adoc#components-provider[Beans built by a supplied factory] — the code-generation coverage reports a bean an extension registers with `addFactory` as `FACTORY` instead of `reflection`: the container never builds it by reflection (VAU-COV-001).
* xref:internals.adoc[Bean classes validated from the index] — the definition rules the container checked by reflecting on every member of every bean class (raw `Event`/`Instance`, producer types, generic initializers, stereotypes, `@Typed`, interceptor binding values…) are checked on the index at boot, with the same messages; a class the index cannot decide is still checked by reflection. `vauban-processor` checks the same rules at build and reports a broken one as a warning, so the build shows what the start would reject (VAU-PERF-008).
* xref:internals.adoc#components-provider[Generic types from the index] — the class-file index reads the `Signature` of fields and methods, so a producer or an injection point of type `List<String>` or `Instance<Repo<T>>` is typed from the index instead of reading its class again by reflection at boot; a producer method is no longer matched by name alone (VAU-PERF-007).
* xref:internals.adoc#components-provider[Private `@Inject` fields without reflection] — the generated `_VaubanComponents` writes a private `@Inject` field through a `VarHandle` it finds once with its own lookup, instead of the container calling `Field.set` at each creation of the bean; the processor no longer warns that such a field needs `opens` (VAU-PERF-006).
* xref:internals.adoc#components-provider[A bean is read once, not at each creation] — the injection order, the lifecycle callbacks, the type-variable mapping, the `@Inject` constructor and the `@AroundConstruct` interceptors of a bean class are worked out once and reused, and `InvocationContext.getInterceptorBindings()` once per method: serving requests no longer reads bean classes by reflection (VAU-PERF-003, -004).
* xref:getting-started.adoc[Annotations from the index] — `VaubanContainer.indexedAnnotationNames(Class)` names the annotations declared on a class as the deployment's index read them from its class file, or answers empty for a class outside the index. An integration can sort bean classes by annotation without reflection: Cassini uses it to find the `@Path` and `@Provider` beans at startup.
* xref:internals.adoc#components-provider[A bean is read once, not at each creation] — the injection order, the lifecycle callbacks, the type-variable mapping, the `@Inject` constructor and the `@AroundConstruct` interceptors of a bean class are worked out once and reused — the injection order and the lifecycle callbacks from the index, each member then looked up directly — and `InvocationContext.getInterceptorBindings()` once per method: serving requests no longer reads bean classes by reflection (VAU-PERF-003, -004).
* xref:internals.adoc#components-provider[Less reflection on the request path] — a primitive `@Inject` field (`@Inject @ConfigProperty int port`) is assigned by the generated `_VaubanComponents` instead of `Field.set` at each creation of the bean (VAU-PERF-002), and the request context's lifecycle events no longer hash `AnnotationLiteral` qualifiers by reflection to tell whether they are observed (VAU-PERF-001).
* xref:concepts.adoc#classes-outside-the-index[Build-time extensions see every class they follow] — at build, a Build Compatible Extension that follows a class from an annotation value (`@JsonbTypeAdapter(AmountAdapter.class)`) sees its members, as at boot, instead of an empty class: an adapter that injects without being a bean is now caught at build (VAU-BCE-008).
* xref:internals.adoc#components-provider[Interceptor methods without reflection] — the generated `_VaubanComponents` calls the `@AroundInvoke`, `@AroundConstruct` and lifecycle interceptor methods of its package, so an interceptor whose methods are package-private works on the module path without opening its package to `io.vidocq.vauban.core` (VAU-INT-011).
* xref:concepts.adoc#inject-constructor[Overloaded `@Inject` constructors] — the injection points of an `@Inject` constructor are typed from that constructor, not from another one with the same number of parameters: an `Instance<T>` parameter no longer fails the deployment as an ambiguous `T` (VAU-DISC-003).
* xref:reference.adoc#beans-of-other-modules[Injection points satisfied by another module] — the static validation now sees the beans of the bean archive modules on the module path, producers included: an application that injects a type produced by a dependency (`JsonWebToken` from cervantes-cdi-vauban) no longer gets the _deferred to the runtime container_ warning at each build. A type nobody provides keeps it.
* xref:reference.adoc#generation-round[Quieter builds] — `vauban-processor` writes its classes before javac's last round, which removes one "created in the last round" warning per generated class (`-Avauban.generationRound=last` restores the former behaviour); what Build Compatible Extensions log at build time becomes one javac message per line instead of java.util.logging's two-line, localized format.
* xref:internals.adoc[Classes generated at run time are announced] — when Vauban has to generate an intercepted subclass, a client proxy or an interface proxy at run time instead of using the class `vauban-processor` generated at build time, it logs a framed warning at the end of the boot listing them (and another for a class generated later that the boot did not foresee), so a module built without the processor is visible at start-up. Producer proxies follow one eligibility rule on both paths, and deployment classes load through the deployment's own loader.
* xref:reference.adoc#beans-of-other-modules[Dependencies read at build time without running them] — the processor loads a dependency's classes without initialising them, and a class it cannot link under javac (a supertype or annotation missing from the processor path) keeps the annotations the index read instead of failing the build (VAU-APT-008).
* *Interceptors* — an interceptor may have an `@Inject` bean constructor (VAU-INT-009); `Interceptor.intercept` lets the exceptions of the invocation through unchanged (VAU-INT-010); an intercepted call resolves nothing again on each invocation.
