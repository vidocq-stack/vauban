= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:concepts.adoc#classes-outside-the-index[Build-time extensions see every class they follow] — at build, a Build Compatible Extension that follows a class from an annotation value (`@JsonbTypeAdapter(AmountAdapter.class)`) sees its members, as at boot, instead of an empty class: an adapter that injects without being a bean is now caught at build (VAU-BCE-008).
* xref:internals.adoc#components-provider[Interceptor methods without reflection] — the generated `_VaubanComponents` calls the `@AroundInvoke`, `@AroundConstruct` and lifecycle interceptor methods of its package, so an interceptor whose methods are package-private works on the module path without opening its package to `io.vidocq.vauban.core` (VAU-INT-011).
* xref:concepts.adoc#inject-constructor[Overloaded `@Inject` constructors] — the injection points of an `@Inject` constructor are typed from that constructor, not from another one with the same number of parameters: an `Instance<T>` parameter no longer fails the deployment as an ambiguous `T` (VAU-DISC-003).
* xref:reference.adoc#beans-of-other-modules[Injection points satisfied by another module] — the static validation now sees the beans of the bean archive modules on the module path, producers included: an application that injects a type produced by a dependency (`JsonWebToken` from cervantes-cdi-vauban) no longer gets the _deferred to the runtime container_ warning at each build. A type nobody provides keeps it.
* xref:reference.adoc#generation-round[Quieter builds] — `vauban-processor` writes its classes before javac's last round, which removes one "created in the last round" warning per generated class (`-Avauban.generationRound=last` restores the former behaviour); what Build Compatible Extensions log at build time becomes one javac message per line instead of java.util.logging's two-line, localized format.
* xref:internals.adoc[Classes generated at run time are announced] — when Vauban has to generate an intercepted subclass, a client proxy or an interface proxy at run time instead of using the class `vauban-processor` generated at build time, it logs a framed warning at the end of the boot listing them (and another for a class generated later that the boot did not foresee), so a module built without the processor is visible at start-up. Producer proxies follow one eligibility rule on both paths, and deployment classes load through the deployment's own loader.
* xref:reference.adoc#beans-of-other-modules[Dependencies read at build time without running them] — the processor loads a dependency's classes without initialising them, and a class it cannot link under javac (a supertype or annotation missing from the processor path) keeps the annotations the index read instead of failing the build (VAU-APT-008).
* *Interceptors* — an interceptor may have an `@Inject` bean constructor (VAU-INT-009); `Interceptor.intercept` lets the exceptions of the invocation through unchanged (VAU-INT-010); an intercepted call resolves nothing again on each invocation.
