= Concepts
:description: Indexer, Processor, ClassLoader SPI, génération bytecode statique.

== Indexer

`vauban-indexer` parcourt le classpath / module-path à la compilation et produit un **index des beans** : classes annotées CDI, leurs scopes, qualifiers, interceptors, decorators. C'est l'équivalent statique du `BeanArchive` runtime de Weld.

== Processor (APT)

`vauban-processor` est un `javax.annotation.processing.Processor` qui consomme cet index et **génère un `_Factory` par bean** via la Class-File API. Le bytecode produit :

* expose un constructeur sans argument ;
* implémente `BeanFactory<T>` ;
* sait instancier la cible avec ses dépendances déjà résolues.

[NOTE]
====
Le runtime ne fait jamais de réflexion sur les beans. Tout ce qu'il instancie passe par les `_Factory` générés.
====

== ClassLoader SPI

`vauban-classloader-spi` (dans `vauban-classloader-spi`) expose `PluginContext`, `ByteSourcePlugin`, `ArchiveReader` — utilisés par `vauban-sjar` pour charger des `_Factory` depuis des archives signées (`.sjar`). Permet d'embarquer des extensions sans `add-opens`.

== Modes scope

CDI 4.1 Lite implémenté :

* `@Singleton`, `@ApplicationScoped` — instances uniques sur la durée du container.
* `@Dependent` — instances multiples, durée de vie alignée sur l'injecteur.
* `@RequestScoped` — fourni quand un transport contextuel est branché (Cassini ou Foy).

== Compatibilité AOT

Pas de `Class.forName`, pas de `Method.invoke`, pas de `Class.getDeclaredFields()` au runtime. Tout passe par `MethodHandles` ou directement par bytecode généré. Compatible :

* GraalVM `native-image` sans `reflect-config.json`.
* Project Leyden CDS.
* JLink minimal images.

== Outillage

* `vauban-maven-plugin` — orchestre le pipeline `index → process → generate → analyze`.
* `vauban-junit` — `@VaubanTest` extension JUnit 5 qui boote un container minimal pour les tests.
* `vauban-test-suite` — suite officielle de tests d'intégration.
